### Семейства подсистем хранения данных

- _журналированные_ (log-structured storage engine),
- _постраничные_ (page-oriented storage engine).

**Журналированная подсистема хранения данных** — это система, которая для обеспечения целостности и надежности данных
ведет постоянную запись всех изменений в виде журнала операций (лога). Этот журнал позволяет восстанавливать
состояние данных после сбоев, обеспечивает атомарность и согласованность операций, а также может использоваться для
репликации и отката изменений.

Для более эффективного поиска могут использовать _хэш-индекс_ (см. [Виды индексов](#виды-индексов)).

Чтобы избежать исчерпания свободного места на жёстком диске, подобные подсистемы разбивают журнал на _сегменты_.  
Данные записываются в последний сегмент, пока он не достигнет определённого размера. Затем сегмент закрывается и 
создаётся новый. Только что закрытый сегмент становится _read-only_.

### Индексы

**Индекс** — это вспомогательная структура данных в системах хранения,
которая ускоряет операции поиска, фильтрации и сортировки данных за счёт предварительного упорядочивания информации о
расположении записей.

#### Виды индексов

**Хэш-индекс** — это тип индекса, основанный на использовании хэш-функции для преобразования значений ключевых полей в
фиксированные значения (хэши), которые служат указателями на физическое расположение соответствующих записей в хранилище
данных.

| Ключ (хэш) | Указатель на значение |
|------------|-----------------------|
| a1b2c3d4e  | 0x1A3F001E            |
| f5e6d7c8b  | 0x1E0000FF            |
| ...        | ...                   |

Каждый раз при добавлении пары ключ-значение, происходит обновление хэш-карты для отображения в ней относиельного
адреса только что записанных данных (как при вставке, так и при обновлении).  
Если требуется найти значение, можно воспользоваться хэш-картой для поиска относительного адреса записи в файле и
затем прочитать её с диска, перейдя по этому адресу.

**Примеры подсистем**: Bitcask (NoSQL СУБД Riak)
