# УРОВНИ ИЗОЛЯЦИИ

## READ COMMITTED

**Частичная изоляция транзакций**, обеспечиваемая режимом Read Committed, подходит для многих
приложений — этот режим
быстрый и простой в использовании.
Read Committed в PostgreSQL **показывает только зафиксированные данные на момент начала запроса**,
обеспечивая
снимок состояния. Транзакция видит собственные изменения, однако **последовательные SELECT могут
возвращать разные данные**.

* Команды UPDATE, DELETE и аналогичные находят строки, зафиксированные на момент начала команды, но
  могут столкнуться
  с обновлениями или удалениями других транзакций, что приводит к ожиданию и повторной оценке.
* В режиме Read Committed команда INSERT с ON CONFLICT может вставлять или обновлять строки.
  Несвязанные транзакции
  могут неожиданно влиять на эти операции. Тем не менее, если нет посторонних ошибок, один из двух
  исходов гарантирован.
* MERGE позволяет условно комбинировать действия INSERT, UPDATE и DELETE. Команда повторно оценивает
  условия для
  обновлённых строк и обрабатывает параллельные обновления и удаления.

## REPEATABLE READ

Уровень изоляции Repeatable Read **видит данные, зафиксированные до начала транзакции**, исключая
незафиксированные
изменения и параллельные обновления, что предотвращает большинство аномалий стандарта SQL.
Repeatable Read использует снимок состояния, созданный при выполнении первого оператора транзакции,
обеспечивая
одинаковый результат для последовательных SELECT и игнорируя изменения, зафиксированные позднее.
Приложения, использующие этот уровень, должны быть готовы к повтору транзакций при сбоях
сериализации.

* Команды UPDATE, DELETE, MERGE, SELECT FOR UPDATE и SELECT FOR SHARE ищут строки, зафиксированные
  на момент начала
  транзакции. Параллельные обновления могут привести к ожиданию транзакции с уровнем repeatable
  read. Откат первой
  транзакции позволяет продолжить выполнение, однако её фиксация делает снимок недействительным, что
  вызывает откат.
* Если приложение получает такую ошибку, оно должно повторить транзакцию с самого начала, чтобы
  учесть ранее
  зафиксированные изменения.
    * Repeatable Read гарантирует стабильное представление базы данных, однако оно может не
      полностью соответствовать
      последовательному выполнению транзакций. Для корректной работы бизнес-логики могут
      потребоваться явные блокировки.

## SERIALIZABLE

Уровень изоляции Serializable обеспечивает наиболее строгую изоляцию транзакций, имитируя
последовательное выполнение
всех зафиксированных транзакций. Он отслеживает несоответствия в параллельных выполнениях,
обнаруживая аномалии,
которые вызывают сбои, при минимальных дополнительных накладных расходах на блокировки.

* При использовании транзакций Serializable данные, прочитанные из постоянных таблиц, не следует
  считать достоверными
  до фиксации транзакции. Это относится ко всем транзакциям, кроме отложенных транзакций только для
  чтения, которые
  гарантируют достоверность данных при их чтении. Приложения не должны полагаться на результаты
  отменённых транзакций
  и должны повторять попытки до успешного завершения во избежание аномалий.
* Механизм предикатных блокировок PostgreSQL выявляет зависимости между транзакциями Serializable
  для предотвращения
  аномалий без вызова блокировок или взаимоблокировок, в отличие от других методов обеспечения
  согласованности.
* PostgreSQL использует _предикатные блокировки_ (SIReadLock, см. `pg_locks`), которые зависят от
  обращений к данным
  и могут быть досрочно сняты транзакциями только для чтения, иногда даже до их завершения.
* Изоляция Serializable в PostgreSQL всё равно может вызывать нарушения ограничений уникальности
  из-за пересекающихся
  транзакций, даже при проверке последовательности выполнения. Для предотвращения этого необходимы
  явные проверки ключей.
  При использовании транзакций Serializable для управления параллельным доступом следует учитывать
  следующее для
  достижения оптимальной производительности:
* По возможности объявляйте транзакции как READ ONLY.
* Контролируйте количество активных подключений, при необходимости используя пул подключений.
* Не включайте в одну транзакцию больше операций, чем требуется для обеспечения целостности.
* Не оставляйте подключения в состоянии «idle in transaction» дольше необходимого. Для
  автоматического отключения
  затянувшихся сессий можно использовать параметр конфигурации
  `idle_in_transaction_session_timeout`.
* Отказывайтесь от явных блокировок, SELECT FOR UPDATE и SELECT FOR SHARE там, где они больше не
  нужны благодаря
  защите, автоматически обеспечиваемой транзакциями Serializable.
* Нехватка памяти может вынудить предикатные блокировки объединяться, увеличивая количество сбоев
  сериализации.
  Увеличение соответствующих параметров поможет избежать этого.
* Последовательное сканирование требует блокировок на уровне отношений, что может вызывать сбои
  сериализации.
  Корректировка стоимости запросов может способствовать использованию индексных сканирований,
  балансируя между
  откатами и временем выполнения запросов.

# СПРАВОЧНИК ПО АНОМАЛИЯМ

Аномалии, которые запрещены на различных уровнях изоляции:

* **Грязное чтение** — транзакция читает данные, записанные параллельной незафиксированной
  транзакцией.
* **Неповторяемое чтение** — транзакция повторно читает ранее прочитанные данные и обнаруживает, что
  они были изменены
  другой транзакцией (зафиксированной после первоначального чтения).
* **Фантомное чтение** — транзакция повторно выполняет запрос, возвращающий набор строк по условию
  поиска, и
  обнаруживает, что этот набор изменился вследствие недавно зафиксированной транзакции.
* **Аномалия сериализации** — результат успешной фиксации группы транзакций не соответствует ни
  одному из возможных
  порядков их последовательного выполнения.
  Уровни изоляции транзакций по стандарту SQL и их реализация в PostgreSQL описаны в следующей
  таблице:
  | Уровень изоляции | Грязное чтение | Неповторяемое чтение | Фантомное чтение | Аномалия
  сериализации |
  |--------------------------|-----------------------------|----------------------|-----------------------------|-----------------------|
  | **Read uncommitted**     | Допустимо, но не в PG | Возможно | Возможно | Возможно |
  | **Read committed**       | Невозможно | Возможно | Возможно | Возможно |
  | **Repeatable read**      | Невозможно | Невозможно | Допустимо, но не в PG | Возможно |
  | **Serializable**         | Невозможно | Невозможно | Невозможно | Невозможно |
